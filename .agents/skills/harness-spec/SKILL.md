# Harn composition

`Harn<C, N, R, P, A, I, D>` is the composition root. It owns the Nucl
coordinator, repository bundle, deferred-task producer, token authentication,
image pool, and effect developer in an `Arc`-backed inner value.

- Keep constructor and accessor order aligned:
  `nucl`, `repo`, `prom`, `auth`, `image_pool`, `develop`.
- `N` implements `Nucl<Context = C, Error = BaseError>`.
- `R` aggregates the active domain `XxxRepo<C>` capabilities generated by the
  repository `#[drive]` declarations.
- `P` implements `Prom<C>`; the remaining generic parameters implement their
  direct port traits.
- `AppHarn` in `src/api/http/state.rs` is the concrete production alias.
  `src/main.rs` must construct every production adapter needed by that alias.
- Add a new harness parameter only when the production composition requires a
  new long-lived port. Do not add a second harness or forwarding layer.
- Use `part_impl::repo::mock_impl::Mock` and module-local fixtures for use-case
  tests instead of creating a parallel test harness.
- Do not instrument constructors, cloning, or plain accessors.

## Review

- [ ] Context and repository capability bounds use the same `C`.
